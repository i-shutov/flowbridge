## Архитектурная основа

Общий Engine, policy и транспорт реализованы на Rust; Windows GUI использует
native Win32 C++, macOS — SwiftUI поверх C ABI. GUI и CLI используют один Engine.
Системные адаптеры должны получать process identity и original destination
от платформы. Для полного Windows выпуска используется WFP/ALE с kernel callout
и службой; macOS Network Extension имеет отдельную платформенную приёмку.

Ближайший explicit-SOCKS кандидат не активирует непроверенный драйвер.
Компиляция, staging, source review, инженерная нагрузка и приёмка
оригинального установленного продукта учитываются отдельно.

## Действующая организация работ

Три параллельных инженерных блока: состав и metadata кандидата; пригодность
доверенного SSH runtime; lifetime/rundown WSK. Изолированную реализацию и
независимую ревизию выполняют субагенты **GPT-6.2 Sol / high**, интеграцию,
сверку доказательств и генеральный план — основной агент.

**Win10 исключён из текущих работ владельцем.** Win11 runner используется
для сборки и инженерных проверок, не заменяя приёмку поддерживаемой платформы.
Локальный Codex на Win11 не является необходимым условием этих заданий.
Режим внутренний: без публичного Release, тега и исполняемых artifacts.
Согласованные 11 artifacts удалены, исходные запуски и журналы сохранены.

Переход между этапами определяется доказанными gates. Даты выпуска и процент
готовности не назначаются без закрытия технических и продуктовых условий.
