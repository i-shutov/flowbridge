**Обновлено: 27 ноября 2026, МСК.** Ближайший результат — проверенный внутренний
`0.3.0-beta.3` с явным SOCKS5 и управляемым SSH. Выпуск `1.0` с прозрачным
перехватом остаётся отдельным этапом. [Машинный реестр выполнения](qa/release-1.0/RELEASE_EXECUTION_20261127.json).

Этот документ заменяет накопленные сводки. Они сохранены в
[истории плана до 17 ноября](RELEASE_1_0_PLAN_HISTORY_20261117.md).
Старые PASS относятся только к указанным там байтам и платформам.

Pro build 22631, native x64 и закреплённая административная учётная запись.
Это подтверждает среду исполнения; продуктовая приёмка остаётся отдельной.

код, но выгрузка артефактов должна требовать private repository. Смена видимости
остаётся решением владельца; локальная приватная сборка может исполняться без неё.

### R1: проверка новой машины

**Выполнено.** Браузерный вход в GitHub подтверждён, runner был `Idle` и принял
ручное задание на `main`. [Первый запуск](https://github.com/i-shutov/flowbridge/actions/runs/45981565644)
не дошёл до проверок: PowerShell отклонил загрузку временного `.ps1` при
`Restricted`. Workflow теперь передаёт команды системному PowerShell через
`cmd` и `-Command`; политика не изменяется. [Повторный запуск](https://github.com/i-shutov/flowbridge/actions/runs/45982267687)
подтвердил Windows 11 Pro build 22631, native x64, точный host/account,
административный token и `RUNNER_SMOKE_PASS`; `Restricted` сохранилась.

В service PATH найдены `ssh.exe` и `python.exe`; не найдены Git, Rust/Cargo,
CMake, MSVC/MSBuild и NSIS. Сам факт нахождения Python ещё не проверяет его
версию и исключение Store alias. [Native preflight #45984099025](https://github.com/i-shutov/flowbridge/actions/runs/45984099025)
нашёл Git, CMake, MSVC x64 и Windows SDK в обычных каталогах установки.
В первой попытке Python 3.13+ и Rust/Cargo не найдены; сборка остановилась до
создания кандидата с `PYTHON_3_13_OR_LATER_REQUIRED`. В R5 эти зависимости
подготовлены из официальных пакетов в отдельном локальном каталоге; пробная
компиляция с MSVC/SDK и полный beta.3 build завершились успешно.

В `main` добавлен [ручной native build workflow](https://github.com/i-shutov/flowbridge/actions/workflows/win11-private-beta3-build.yml),
первый commit `ee218fcffe9c7d2d69821824ea693698bc382098`, успешная версия
`7d6597eb738d16839ff7a969c5ff6644194df975`. Он использует закреплённые QA
и product SHA, сохраняет результат вне Actions workspace в новом каталоге
с отдельными ACL и не выгружает пакет. Предварительный поиск инструментов
не является доказательством компиляции сам по себе; фактические результаты R5/R6
приведены ниже.

Smoke workflow не делает checkout и не запускает код PR. Отдельная сборка
получает закреплённые product/QA SHA. Smoke доказывает работу
службы и окружения; интерактивный GUI проверяется локальным Codex в пользовательской
сессии. Успех службы в Session 0 не является GUI-приёмкой.

GitHub-коннектор не предоставляет dispatch/list-runners/delete-artifact;
для этих операций используется авторизованный браузер. Административный runner
получает только вручную запущенный workflow с проверками точного repo и `main`.

### R2: устранение несогласованной публикации CI

После merge #90 автоматически запустился прежний `main` CI и успел выгрузить
артефакты, включая `FlowBridge-windows-x64` и исходный архив. Это не beta.3
и не принятый релиз, но выгрузка противоречит внутреннему режиму.
Запуск [#45975037904](https://github.com/i-shutov/flowbridge/actions/runs/45975037904)
отменён последующим исправлением; API перечислял 11 артефактов. Их удаление
ещё не выполнено; точные ID записаны в реестре для очистки. Вход уже выполнен,
но подтверждение безвозвратного удаления пока не получено. Удалять только
эти 11 артефактов; журналы и исходные коммиты сохраняются.

Новый `main` CI разрешает upload только при
`github.event.repository.private == true`. В продуктовой ветке такая защита
внесена во все 29 upload-шагов. Сборки и тесты продолжают выполняться.
Количество новых артефактов проверять отдельно от результата тестов.

На проверенных current source/QA запусках API подтвердил 0 артефактов после
завершения. Точные результаты и ссылки сохранены в
[CI observation](qa/release-1.0/evidence/20261127/ci-observation.json).
Source Rust/native прошёл 5/5 после повторного запуска только Windows job
на прежнем дереве: первый `WinError 10013` в paired DNS test не повторился.
Причина первого сбоя не установлена. Managed SSH прошёл; отдельный raw512
тест потерял соединение на 244 каналах, а hosted G2 ETW остаётся непроверенным.
Эти два отказа не преобразуются в PASS на основании успешного staging.

### R4–R6: воспроизводимая приватная сборка

Использовать два checkout: закреплённый продуктовый source и QA-инструмент.
[`stage_internal_beta3.py`](../tools/stage_internal_beta3.py) проверяет source SHA,
чистоту, девять версионных файлов, семь пакетов workspace в Cargo.lock,
пустой список remotes и неприсвоенные release flags.
[Команды и входные данные](qa/release-1.0/checkpoints/WIN11_BETA3_BUILD_RUNBOOK_20261127.md).

Исправления 27 ноября:

- Отрицательный тест версии подставляет неверную версию и после перехода на `.3`.
- Индекс Git строится из точных blobs без фильтров с сохранением executable mode:
  четыре исторических CRLF-файла больше не переписываются молча.
- Полное дерево проверяется по path/mode/blob; пакетные тесты запускаются
  на действительно подготовленном beta.3 source.
- Для локальной сборки обязательны официальный NSIS 3.13 ZIP с закреплённым
  SHA-256 и Windows client x64. NSIS извлекается отдельно, глобальный PATH не
  меняется. Windows Server не засчитывается как client acceptance.

**Нативная сборка завершена 27 ноября, 14:01 МСК.** [Запуск на Win11](https://github.com/i-shutov/flowbridge/actions/runs/45986630920)
прошёл; GitHub Actions artifacts — 0. Python 3.13.17, Rust 1.100.0 и официальный
NSIS 3.13 проверены перед использованием; использованы установленные MSVC/SDK/CMake.

- Исходный manifest, GUI/CLI/FFI и все 13 файлов payload повторно проверены;

## 4. Приёмка beta.3 на Win10

1. Проверить фактические Windows build/обновления и выбранный OpenSSH runtime:
   подпись, хеш, доверенный системный либо явно заданный путь.
2. На одном наборе SHA выполнить install, payload verification, launch, upgrade,
   uninstall и сохранение существующего стабильного профиля.
3. Проверить GUI Ready/Failure/Recovering, Save/Cancel, журнал, клавиатуру и мышь
   при 980×680 и 1366×768. Изображения должны относиться к новому EXE.
4. Проверить настоящий managed SSH/SOCKS5h, неправильный host key, отсутствующий
   identity file, недоступный сервер и all-workers-down. Записать наблюдаемый
   трафик; loopback smoke не доказывает универсальный DNS/no-leak.
5. Проверить отсутствие сырых stderr/приватных путей в экспортируемой диагностике,
   Stop/cleanup и восстановление profile/ACL/registry.
6. Приватно сохранить оригинальные JSON, изображения и хеши; провести независимую
