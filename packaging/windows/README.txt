FlowBridge 0.2.0 • Windows x64

БЫСТРЫЙ СТАРТ
В FlowBridge четыре раздела: «Обзор», «Подключение», «Приложения»,
«Журнал и JSON». Кнопка «Подключить» всегда находится справа вверху.
В меню слева можно переключить светлую и тёмную тему.

1. Откройте «Подключение» и выберите способ работы:
   • Готовый внешний прокси: укажите host, port и SOCKS5 / HTTP CONNECT /
     SOCKS4a. Прокси должен быть уже запущен; FlowBridge им не управляет.
   • SSH с автовосстановлением: укажите SSH-сервер, порт, пользователя,
     приватный ключ или используйте SSH agent. Выберите known_hosts, если
     стандартный файл OpenSSH не подходит. Локальный SOCKS-порт по умолчанию 1080.
2. Для SSH нужен установленный Windows OpenSSH Client (ssh.exe), доступный
   приложению. Ключ сервера должен быть проверен заранее и находиться в
   known_hosts. При первом подключении используйте обычный ssh в терминале,
   сверяйте fingerprint сервера с администратором по независимому каналу.
   FlowBridge не принимает неизвестные/изменившиеся ключи автоматически.
   Поддерживаются ключ / agent; интерактивный ввод пароля не поддерживается.
3. Нажмите «Сохранить подключение» или сразу «Подключить». В режиме SSH
   сначала запускается и проверяется SSH/SOCKS5; только затем запускается
   локальный движок. «Подключено» означает реально работающий listener.
4. Укажите в нужных клиентских приложениях SOCKS5 127.0.0.1:1081. Это listener
   FlowBridge; его порт отличается от локального SSH upstream-порта 1080.
   Например: curl --socks5-hostname 127.0.0.1:1081 https://example.com
5. В «Обзоре» видны состояния SSH, реальные текущие/недавние соединения и
   счётчики трафика. «Остановить» завершает движок, затем SSH. Закрытие окна
   также останавливает оба компонента; в фоне приложение не остаётся.

SSH WATCHDOG
FlowBridge следит за дочерним OpenSSH и доступностью его SOCKS5 listener.
При обрыве он повторно запускает SSH с растущей паузой. В форме задаются
интервал keepalive, число пропусков, начальная и максимальная пауза повтора,
а также сжатие. Явная остановка отменяет повторные подключения.
Во время переподключения движок и его локальный listener остаются запущены.
Новые соединения через этот SSH upstream могут ждать готовности до 30 секунд,
затем получают ошибку, если upstream не восстановился. Direct/Block не ждут SSH.
Уже существовавшие TCP-соединения после обрыва восстановить невозможно;
клиентское приложение должно создать их заново. FlowBridge не воспроизводит
записанные запросы и не обещает бесшовного сохранения TCP-сеансов.
Меняйте SSH-параметры и способ подключения после остановки.

ПРИЛОЖЕНИЯ И AI / WEB ШАБЛОНЫ
При первом открытии «Приложений» запускается ограниченный локальный поиск.
Используются App Paths и Uninstall в реестре, известные ярлыки меню «Пуск»,
пути запущенных процессов. Сеть, весь диск и содержимое файлов не сканируются.
Показываются реальный обнаруженный путь, источник и эвристическая уверенность.
Сопоставление имени EXE не подтверждает производителя или безопасность файла.
Шаблоны «AI-приложения», «Веб-браузеры», «AI + веб» отмечают найденные
совпадения. Проверьте выбор; любой EXE можно добавить через «Добавить EXE».
Новые/необычные способы установки могут не обнаружиться автоматически.

НАТИВНЫЙ ПЕРЕХВАТ — ЗАКРЫТАЯ ТЕСТОВАЯ ВЕРСИЯ
Комплект содержит FlowBridgeCapture.exe и кнопку «Нативный перехват»,
но обычный установщик НЕ устанавливает WFP-драйвер. Для реального
перенаправления выбранных EXE необходим отдельно установленный и разрешённый
Windows подписанный или тестово подписанный WFP-драйвер на выделенной
тестовой машине. Без такого драйвера helper честно завершится с ошибкой;
кнопка и успешная сборка не доказывают системный перехват.

В режиме «SSH с автовосстановлением» сначала нажмите «Подключить» и
дождитесь состояния «Готов». Затем в «Приложениях» отметьте EXE и
нажмите «Нативный перехват». FlowBridge попросит UAC только для WFP helper.
SSH, его конфигурация, пользовательский ключ и known_hosts остаются у
обычного GUI. Helper направляет выбранные TCP-потоки через существующий
локальный SOCKS FlowBridge; при ошибке upstream нет автоматического DIRECT.
Сначала останавливайте нативный перехват, затем SSH. При закрытии окна GUI
ожидает прекращения helper перед завершением SSH.

В режиме внешнего SOCKS подключать локальный движок необязательно:
helper использует заданный внешний upstream. Нативный захват и обычная
передача через вручную настроенный SOCKS — разные способы подключения.
Экспорт JSON профиля не запускает WFP. Выбор приложений работает по полному
пути EXE в фильтре WFP, затем правила маршрутизации используют basename;
одинаковые имена EXE не считаются одним приложением для отбора в WFP.

Важно: пока не подтверждены испытания установленного WFP-драйвера на
авторизованной VM, DNS-перехват выбранных приложений, QUIC/UDP и поведение
при разных DPI. Обычный TCP WFP-захват сам по себе НЕ защищает DNS-запросы,
выполненные приложением до connect; зашифрованные DoH/DoT не дешифруются.
Это приватная бета, не публичный релиз.

ПРОФИЛИ И ПРАВИЛА
«Журнал и JSON» содержит полный JSON: listener, upstream-прокси,
цепочки, правила, таймауты и окружение для паролей внешних прокси.
«Применить профиль» проверяет и перезагружает профиль без запуска.
«Открыть JSON» загружает черновик; «Экспорт JSON» сохраняет черновик.
Подключение / применение сохраняет принятый профиль:
  %LOCALAPPDATA%\FlowBridge\profile.json
SSH, тема и выбранные приложения сохраняются отдельно:
  %LOCALAPPDATA%\FlowBridge\desktop-settings.json
Ключи и пароли не копируются в эти настройки; там только пути и параметры.
Ошибочный reload сохраняет прежнюю конфигурацию движка. Для изменения
listener/max_connections сначала остановите движок. Существующие соединения
при reload сохраняют первоначальный маршрут. В управляемом SSH режиме
default_action указывает managed-ssh; явные правила JSON могут это изменить.
Application-критерии отклоняются локальным SOCKS-движком, поскольку он не
может достоверно определить исходный процесс. Нативный экспорт — отдельный файл.
Журнал/список соединений ограничены; обычное обновление примерно раз в секунду.

ГРАНИЦЫ РЕЖИМА
Приложение не меняет Windows proxy, DNS, VPN, firewall или автозапуск.
Драйвер не устанавливается. Гарантии отсутствия DNS-утечек нет: поведение DNS
зависит от клиента; --socks5-hostname у curl передаёт hostname через SOCKS.
Приложение/движок не запускаются автоматически после установки.

CLI / УСТАНОВКА / УДАЛЕНИЕ
flowbridge-cli.exe --help показывает доступные команды. Примеры JSON находятся
в папке examples. Установка выполняется для текущего пользователя; ярлыки
появляются в меню «Пуск». Закройте GUI и CLI перед обновлением/удалением.
Инсталлятор проверяет mutex GUI в текущем сеансе и не закрывает его принудительно.
Деинсталлятор сохраняет профили/desktop-настройки и не удаляет посторонние файлы.
Пакет не подписан, если дистрибьютор отдельно не подписал его бинарные файлы.
Это настоящий Win32 GUI с Rust C ABI; кросс-компиляция и Wine не заменяют
проверку на настоящей Windows и проверки подписанного нативного backend.

INTERNAL BETA CAPTURE HELPER
FlowBridgeCapture.exe is included as a user-invoked UAC helper. It does not
install, enable, trust, or sign a Windows kernel driver. The regular NSIS
installer leaves system filter policy, driver services and DNS untouched.
In the Applications tab choose an installed EXE, then Native capture. The
helper requires the separately installed, approved WFP kernel callout; when
missing, its console reports a driver failure and exits. Closing the GUI or
pressing Stop signals the helper to remove this process's dynamic filters.
Other applications are not covered by the selected-EXE capture filter.
Do not confuse a successful GUI/helper build with real driver redirection QA.
For a read-only check run: FlowBridgeCapture.exe --preflight
