# WFP accepted WSK socket binding prototype

The ABI4 broker accepts a Windows socket and asks the transport for redirect data. Its terminal IOCTL then sends copied context to the driver. A successful ABI4 claim identifies an existing kernel AUTH ticket. The driver cannot inspect the socket object through that IOCTL. The Win11 owned-socket ALE probe verified a useful property of the public transport handle. G2 still requires a kernel-owned path from the accepted socket through the origin receipt and the physical flow.

This directory builds an isolated WDK object, outside the product driver and installer. A future kernel worker can supply a privately owned WSK listener and its immutable policy-generation identity to `FbWskAcceptBound`. The prototype takes the accepted object from the completed `WskAccept` IRP. It checks the returned listener address, then asks WSK for the context and opaque records on that same object. Only a successful exact-size context query and a nonempty record query within the 4 KiB cap reach the ABI4 terminal receipt logic. The lock protects the live process epoch, policy check and one-use terminal update together.

## Ownership and shutdown

Initialize one `FbWskBindingLifetime` per owned listener. `FbWskAcceptBound` shares one three-second completion-wait budget across accept and both queries. Windows scheduling, clock granularity, and time spent in WSK dispatch calls govern when the caller actually returns. Rejection or timeout after allocation transfers a cleanup-only handle to the caller and leaves the bound result empty. The pending IRP, accept address, completion event and query buffers stay in nonpaged storage. `FbWskReleaseBound` moves a successful binding to the same cleanup path and clears the bound handle.

The owner advances cleanup with `FbWskDrainBound` until it consumes the handle or reports a close failure. Each invocation observes completion without waiting. A step can invoke provider code through `IoCancelIrp` or `WskCloseSocket`, so run drain on the owner side of the timeout response. The owner serializes and synchronizes each handle handoff, and schedules further drain calls when the result is `STATUS_PENDING`. Cancellation is requested at most once per abandoned accept or query. Cleanup collects a socket from an accept that succeeds late, discards late query results and issues close once after the previous IRP completes. Resources remain owned until actual completion and successful close when a socket was acquired. A completed close failure leaves the cleanup handle quarantined and retains its outstanding count. Provider completion or close can remain unresolved indefinitely.

`FbWskStopBinding` closes admission and reports `STATUS_DEVICE_BUSY` with the outstanding count while any admitted, bound, draining or quarantined handle remains. Admitted work can still commit until the caller disarms policy under its authority lock. A zero count covers binding resources only. `FbWskComplete` signals its event before it returns, so the driver needs separate rundown that ensures completion and event callbacks have returned before its code can unload. The driver also needs to close the listener, join its callers and worker, release the provider NPI, and wait for `WskDeregister` to return before unloading. The caller holds listener, provider and policy rundown for the lifetime of each handle. It must bind the listener's owning process and exact loopback port to the same redirect target PID and policy generation at the WFP callout. Each armed generation needs its own receipt history.

Signing, real WSK listener startup, redirect record lineage, a native cross-socket transplant attempt, outbound record install, and independent egress evidence remain open. The operating system needs to demonstrate that direct or sibling sockets and a new outbound socket carrying copied records cannot present a valid origin context to the accepted WSK path. Route generation and WSK provider lifetime must be wired and reviewed before any signed runtime test. The current ABI4 driver and its legacy user-mode IOCTL remain outside this prototype.

## Verification

`cmake -S tests/wsk_binding -B BUILD`, build, and CTest exercise nine authority fixtures and nine lifecycle fixtures. Authority fixtures cover single-use authorization, replay, initial AUTH, PID reuse, generation, disable, broker mismatch, wrong flow, malformed context, and IPv4/IPv6 listener mismatch. Lifecycle fixtures cover completion before and after cancellation, late socket ownership, exactly-once close, query timeout, rejected and bound handle cleanup, failed close quarantine, and the admission gate. `python tests/wsk_binding/test_object_source.py` guards the WDK call sites against eight authority substitutions and twelve lifecycle substitutions. The portable fixtures exercise shared decisions with controlled inputs. The hosted WDK target produces a transient object file. Native completion races, cancellation, close, and the unload sequence still require Windows runtime evidence.
